{# The page frame (roadmap M4.5, theming M4.8). Three things here are load-bearing and easy to undo by accident: * Every script is a `src=` to `/static`, never inline. `script-src 'self'` blocks inline scripts, so htmx is configured through the `htmx-config` meta tag and our own component registration lives in `/static/app.js`. The first `` added for debugging will silently do nothing and look like a bug in something else. * `theme.js` is the one script **not** deferred, and that is deliberate. It applies the saved theme to `` before the first paint; deferred, it would run after the page had already been painted in the system theme and every load would flash. It is kept tiny for exactly that reason -- it is a blocking script on every page. * `theme-color` and the stylesheet are first-party. No font CDN, no icon CDN. The static scan in `tests/web/test_static.py` reads this file and fails on an external host, which is the point at which it costs nothing to fix. #} {# Both schemes declared, so form controls, scrollbars and the canvas behind the page follow the theme rather than staying light under a dark layout. #} {# allowEval:false turns htmx's two eval-backed features into a loud htmx:evalDisallowedError rather than a silent CSP refusal in a console nobody has open. {# Where a card modal lands (M4.6). Empty on every server render: the fragment is fetched on click, so nothing here costs anything until somebody opens a card, and a page whose HTML already contained every card's detail would be a page that had to be re-rendered whole to change one. `x-data` lives on the host rather than inside the fragment because htmx replaces the fragment's markup on every open; a component declared inside would be torn down and rebuilt, and the escape-key listener with it. #}
